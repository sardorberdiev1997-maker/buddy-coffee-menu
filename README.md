# Buddy Coffee — онлайн-меню и заказы

Сайт: **https://buddycoffee.uz** (сюда ведут QR-коды на постерах; старый адрес buddy.cheking.uz перенаправляет сюда). Telegram-бот: **@buddy_coffee_uz_bot** (тот же сайт как Mini App).

## Как поменять меню (для владельца)

Всё меняется в Google Таблице «Buddy Coffee — меню» (она в Google Диске владельца; ссылку здесь не публикуем —
репозиторий открытый, а в таблице есть вкладка с клиентами). Сайт подхватывает правки сам, обычно в течение минуты.

- Вкладка «Меню»: цены, названия, описания, вес, метки, наличие («нет» — позиция станет серой).
- Вкладка «Меню»: ещё КБЖУ (ккал, белки, жиры, углеводы) и аллергены.
- Вкладка «Настройки»: шапка, телефон, часы, Wi‑Fi, соцсети, объявление, юрлицо; для заказов — `заказы` (да/нет), `мин_заказ`, `время_доставки`, `время_самовывоза`, `координаты`.
- Подробности — на вкладке «Инструкция».
- Заголовки колонок и ключи настроек защищены предупреждением: их менять нельзя, иначе сайт не прочитает таблицу.

Доступ к таблице: сейчас «все, у кого есть ссылка — редактор» (решение владельца сайта, риск принят: ID таблицы виден в коде сайта). Безопаснее — «по ссылке: читатель» и редактор только по Gmail. Цены заказа сервер всё равно берёт из таблицы, а не из браузера.

## Как устроено

```
Google Таблица ──(export CSV в браузере)──► сайт обновляет меню на лету
      ├─(при каждой сборке Cloudflare)──► меню вшивается в index.html
      └─(GitHub Action каждые 15 мин)──► data/menu.json ──► git push ──► Cloudflare Pages: npm run build ──► dist/
```

- **Хостинг:** Cloudflare Pages, проект `buddy-coffee-menu` (сборка `npm run build`, папка `dist`, Node 20). Каждый push в `main` — новая сборка. Резервный адрес: https://buddy-coffee-menu.pages.dev
- **Домен:** `buddycoffee.uz` — куплен на ahost.uz (продление ежегодно до 31 октября), DNS — в Cloudflare (`jocelyn.ns.cloudflare.com`, `remy.ns.cloudflare.com`), привязан к проекту Pages как Custom domain; `www.buddycoffee.uz` → `buddycoffee.uz` правилом Redirect Rules.
- **Старый адрес** `buddy.cheking.uz` (CNAME `buddy` → `buddy-coffee-menu.pages.dev` в DNS cheking.uz на ahost.uz) оставлен для старых QR-кодов и ссылок: страницы перенаправляет `assets/boot.js` (с путём, параметрами и `#hash` Mini App), короткие ссылки `/r/*` и звонки `/c/*` — сервер ответом 301, `/api/*` работает на обоих адресах. Пока он нужен, cheking.uz надо продлевать.
- **Сборка** (`tools/build.mjs`): берёт меню прямо из Google Таблицы (при сбое — из `data/menu.json`) и вшивает его в `index.html` (страница показывается сразу, без ожидания данных), встраивает CSS и `boot.js` в HTML и добавляет их sha256 в CSP, минифицирует JS/CSS (esbuild), ставит хеши версий для кэша, кладёт `_headers` (CSP, HSTS, X-Frame-Options и др.). Правила View Transitions лежат в `assets/vt.css` отдельно: валидатор W3C пока не знает этот синтаксис.
- **В браузере** (`assets/app.js` + общий `assets/render.js`): меню из HTML → кэш прошлого визита → свежие данные из таблицы (перерисовка только если что-то изменилось). Языки UZ/RU, поиск, шторка блюда, офлайн-режим (`sw.js`).
- **Запасная копия** `data/menu.json` — обновляется GitHub Action'ом `.github/workflows/sync-menu.yml` (`tools/sync_menu.py`). Если 60 дней в репозитории нет коммитов, GitHub отключит расписание и пришлёт письмо — включить в Actions одной кнопкой.
- **«С этим берут»** в карточке блюда: колонка `с_этим_берут` — во вкладке «Категории» (для всей категории) и «Меню» (для блюда, важнее). Названия через «/», до 3 штук, то, чего нет в наличии, не показывается.
- **Отзывы:** ключи `отзыв_google`, `отзыв_yandex`, `отзыв_2gis` во вкладке «Настройки» — жёлтый блок «Понравилось?» с кнопками над контактами. Пустой ключ — кнопки нет.
- **Статистика:** Cloudflare Web Analytics (без cookie) — dash.cloudflare.com → Analytics → Web analytics → buddycoffee.uz.
- **Фото:** `img/xs` (240 px), `img/s` (360 px), `img/l` (960 px) в AVIF и WebP. Кэшируются на год — при замене фото давать файлу новое имя. В таблице в колонке «фото» — имя файла без расширения, прямая ссылка на картинку или ссылка на файл Google Диска с доступом по ссылке.
- `print/` — QR-коды с логотипами (`tools/make_qr.py`, проверка распознавания — `swift tools/check_qr.swift файл.png`); `print/posters/` — постеры A4/A3/A2, карточки A6/A5, домик на стол и наклейка в светлой и тёмной версии: PDF с вылетами 3 мм для типографии и PNG 300 dpi (`tools/make_posters.py`).

## Заказы и доставка

```
Сайт / Telegram Mini App ──POST /api/orders──► dist/_worker.js (Cloudflare Pages) ──► D1 (orders)
                                                 │  проверяет цены и наличие по Google Таблице
                                                 └──► Telegram: сообщение в группу кафе с кнопками статусов
Группа кафе ──кнопки──► /api/tg (вебхук) ──► статус ──► карточка покупателю в боте + страница /order?t=…
buddy-cron (Worker, каждую минуту) ──► /api/tick: напоминания, сводки в 00:00, просьбы об оценке, рассылки,
                                         сторож бота, свежий кэш меню, удаление личных данных через 90 дней
```

- **Код:** `server/` (собирается в `dist/_worker.js`, обслуживает `/api/*`, `/r/*` и `/c/*` — `dist/_routes.json`), общие правила заказа — `assets/order.js` (зона доставки, телефон, расчёт, статусы), корзина — `assets/cart.js`, страница заказа — `order.html` + `assets/track.js`.
- **Правила:** доставка бесплатная, только по городу Шахрисабз (граница из OpenStreetMap, relation 15602076, запас 400 м), минимум 40 000 сум (только доставка), оплата наличными или переводом при получении, 24/7.
- **Статусы:** доставка — принят (ETA 15/30/45/60) → готовится → передан курьеру → в пути → доставлен; самовывоз — принят → готовится → готов к выдаче → выдан; отмена с причиной; «шаг назад» 15 минут.
- **Покупателю в Telegram:** прежняя карточка удаляется, новая приходит вниз чата; со звуком — принят, в пути, готов, доставлен/выдан, отменён; «готовится» и «у курьера» — тихо.
- **Бот в группе:** `/bind` (подключить группу, нужен админ), `/stats`, `/orders`, `/stop`, `/rush`, `/pause`, `/resume`, `/lang`, `/unbind`, `/help`.
- **Стоп-лист и час пик** (`server/live.js`, любой сотрудник в группе): `/stop` — блюда кнопками, нажали — сразу «нет в наличии» на сайте и в Mini App, заказ с ним сервер не примет; само возвращается в 06:00 по Ташкенту (надолго — «в_наличии: нет» в таблице). `/rush` — +15 или +30 минут к срокам на сайте, предупреждение в корзине, кнопки «принять» сдвигаются; выключается само через 3 часа. Оба — в D1 (kv `stoplist`, `rush`), сайт получает их в `/api/state`.
- **Воронка** в `/stats` и сводках: открыли меню → положили в корзину → начали оформление → заказали. Браузер отправляет каждое событие раз за визит на `/api/ev`; на сервере только счётчики по дням (`ev:<день>:<событие>`), без данных о людях; хранятся год. Сводки: день — каждый день в 00:00 (Ташкент), неделя — по понедельникам, месяц, квартал, год — в начале периода.
- **Защита:** цены и наличие только из таблицы, лимит 4 заказа / 10 мин на номер и 10 на IP, скрытое поле от ботов, Origin-проверка, секрет вебхука (HMAC от токена), подпись Mini App initData, повторная отправка формы не создаёт второй заказ.
- **База клиентов:** таблица `customers` (по телефону и по Telegram): заказы, сумма, средний чек, давность, любимое блюдо, сегмент (VIP / Постоянный / Новый / Уснувший / Ушедший), подписка на акции. В группе: `/clients` — Excel-файл, `/sheet` — формула `=IMPORTDATA(...)` для закрытой вкладки «Клиенты» в Google Таблице (ссылка с секретным ключом, `/sheet new` — новый ключ).
- **Рассылки:** администратор пишет сообщение в группе и отвечает на него `/broadcast` → выбор аудитории (все подписчики / активные за 30 дней / уснувшие) → «Пробное мне» → подтверждение. Отправка порциями по 25 (сразу и каждую минуту из `/api/tick`), у клиента — кнопки «Открыть меню» и «Отписаться»; `/stop` и `/subscribe` в боте. Заблокировавшие бота отмечаются и больше не получают. Клиентам только с сайта (без Telegram) рассылка не уходит — для них нужен SMS-провайдер.
- **Звонок клиенту:** под каждым заказом в группе — кнопка «📞 Позвонить клиенту». Ссылку `tel:` Telegram в кнопках не разрешает, а номер в тексте нажимается не везде (Telegram Desktop, часть телефонов), поэтому кнопка ведёт на `/c/<токен заказа>` (`server/call.js`): страница сразу открывает набор номера, а если браузер не дал — крупная кнопка с номером. Телефона в ссылке нет; через 90 дней номер стирается, и страница отвечает «номер недоступен».
- **Оценка и отзывы** (`server/ratings.js`, таблица `ratings`): через 45 минут после доставки бот тихо просит оценить заказ 1–5 (одному человеку не чаще раза в сутки, заказы старше суток не трогаем). Оценка 1–3 сразу уходит в группу «⚠️ Низкая оценка» — с причиной (остыло, долго ждал…), комментарием, именем и телефоном, чтобы позвонить и извиниться; если гость поднял оценку, то же сообщение меняется на «изменил оценку». Ссылки на Google, Яндекс и 2ГИС видят **все** при любой оценке: звать на карты только довольных запрещают правила Google; вознаграждение за отзыв — тоже. Показываются только площадки со ссылкой в «Настройках» (`отзыв_google`, `отзыв_yandex`, `отзыв_2gis`), кнопки ведут на короткие ссылки `/r/google` и т. п. — их же печатают на постерах, поэтому настоящие ссылки можно вписать в таблицу позже, не перепечатывая. Пока ссылки нет, короткая ссылка с постера открывает точку кафе на этой карте по «координатам» (Google — метка, Яндекс — «Что здесь», 2ГИС — точка), а кнопки отзывов на сайте и в боте не показываются. То же — на странице заказа (`/order`) для тех, кто без Telegram. Оценить или изменить оценку можно неделю. Средняя оценка — в `/stats` и сводках; комментарии стираются через 90 дней.
- **Меню при закрытом доступе к таблице:** вкладки «Меню», «Категории», «Настройки» опубликованы в интернете как CSV (`pub` в `assets/config.js`); сайт, сервер и сборка читают их по опубликованным ссылкам, поэтому саму таблицу можно открыть только нужным людям. Публикация обновляется с задержкой до ~5 минут.
- **Личные данные:** адрес, точка и комментарий в заказах обнуляются через 90 дней, имя и телефон остаются в базе клиентов (это сказано на сайте); IP и телефон для лимитов и статистики хранятся только в виде хеша с солью. Сейчас (тестовый запуск) — Cloudflare D1; после запуска — перенос на серверы в Узбекистане (закон «О персональных данных», ст. 27¹).

### Настройка Cloudflare (один раз)

1. D1: база `buddy-orders` → проект Pages `buddy-coffee-menu` → Settings → Bindings → D1 database, имя переменной `DB` (Production и Preview). Таблицы создаются сами.
2. Секрет `BOT_TOKEN` (токен @BotFather) → Settings → Variables and Secrets → тип Secret.
3. После деплоя открыть `https://buddycoffee.uz/api/tg/setup` — ставит вебхук, команды и кнопку «Menyu».
4. В группе кафе (бот добавлен) администратор отправляет `/bind`.
5. Worker `buddy-cron` (код — `cron/worker.js`), Settings → Triggers → Cron `* * * * *`.

Проверка: `https://buddycoffee.uz/api/tg/info` — доходят ли сообщения от Telegram (`pending`, `last_error`), подключена ли группа, когда последний раз работал cron (`last_tick`), какие сводки ушли в группу (`reports`), насколько свежее меню в кэше сервера (`menu_cache_age_s`), сколько раз бот попросил оценку (`rating_requests`), что нашёл сторож бота (`bot_problem`) и последние ошибки JavaScript у посетителей (`client_errors`).

**Сторож бота** (`server/health.js`, раз в 10 минут из `/api/tick`): если вебхук Telegram сброшен (например, токен подключили к другой программе), ставит его заново сам; если Telegram не может доставить сообщения нашему серверу — пишет в группу «⚠️ Бот не получает сообщения» (не чаще раза в 6 часов). **Ошибки у посетителей:** `assets/boot.js` отправляет ошибки JavaScript на `/api/log` — без личных данных (текст ошибки, файл, страница, тип устройства), одинаковые — одной записью в час, не больше 30 в час, хранятся неделю; сетевые сбои мобильного интернета и чужие скрипты (расширения браузера) не отправляются. Подключить группу (`/bind`) можно 30 минут после первой настройки (`/api/tg/setup`); перенести заказы в другую группу — `/unbind` в прежней группе, затем `/bind` в новой (тоже 30 минут). Повторный `/api/tg/setup` окно не открывает — чужой не перехватит заказы. Бот: @buddy_coffee_uz_bot (токен — у владельца сайта в @BotFather).

## Стандарты

- WCAG 2.2 AA: контраст ≥ 4.5:1, семантика (h1–h3, кнопки), фокус, `prefers-reduced-motion`, объявления результатов поиска.
- Безопасность: CSP без inline-скриптов (кроме встроенных по sha256), `frame-ancestors` — только свой сайт и web.telegram.org (Mini App), HSTS, nosniff, Permissions-Policy (геолокация — только своему сайту); ссылки из таблицы фильтруются (http/https/tel/mailto); сторонний JS — только скрипт Telegram и только внутри Mini App.
- КБЖУ — примерные значения на порцию (USDA FoodData Central, стандартные рецепты), аллергены — 14 по Регламенту ЕС 1169/2011, с пометкой о следах.
- Производительность: меню в HTML, свой шрифт, AVIF + srcset, долгий кэш для файлов с хешем.
- SEO: canonical, hreflang uz/ru, Open Graph, schema.org `CafeOrCoffeeShop` + `Menu`, `robots.txt`, `sitemap.xml`.
